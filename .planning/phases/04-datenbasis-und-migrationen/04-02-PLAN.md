<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> `/api/system/status` via Vite proxy | Untrusted browser code receives readiness data from the backend through a dev proxy. |
| Playwright orchestration -> local backend process | Test automation spawns real application processes and must point at the intended local services only. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-05 | S | Frontend success state | mitigate | Render the success badge only from the real `/api/system/status` response shape, and keep explicit loading/error states so the UI cannot spoof readiness without a successful backend roundtrip. |
| T-04-06 | T | Vite proxy routing | mitigate | Restrict the proxy to `/api` and target `127.0.0.1:8080` explicitly so frontend status calls cannot drift to ad-hoc origins or bypass the local backend contract. |
| T-04-07 | R | Phase-4 reachability proof | mitigate | Add `system-status.spec.ts` as a durable Playwright regression so future changes must keep the visible end-to-end readiness path green. |
| T-04-08 | D | E2E process startup | accept | Starting backend + frontend for this targeted spec adds some local test runtime, but the tradeoff is acceptable because the phase requires a real multi-process reachability proof. |
</threat_model>
