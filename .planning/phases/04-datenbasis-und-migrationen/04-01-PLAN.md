<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| backend runtime -> PostgreSQL container | Untrusted infrastructure state crosses into the application through JDBC configuration and schema creation. |
| backend runtime -> Mailpit SMTP | Local mail transport is reachable from the app and must stay local-only with no real delivery side effects. |
| browser/frontend -> system status endpoint | A public read endpoint exposes readiness information and must not leak sensitive health details. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | T | Flyway baseline schema | mitigate | Use versioned Flyway migration files plus `spring.jpa.hibernate.ddl-auto=validate` in `application.yml`, so ad-hoc schema drift cannot silently replace the migration contract. |
| T-04-02 | I | `/api/system/status` | mitigate | Return only a narrow DTO with coarse `UP/DOWN` readiness fields and keep raw actuator/database details out of the browser-facing contract. |
| T-04-03 | D | Backend startup path | mitigate | Align `docker-compose.yml` defaults with Spring datasource settings and prove startup via `SystemStatusIntegrationTest` against a real PostgreSQLContainer. |
| T-04-04 | T | Local SMTP routing | accept | Mailpit remains local-only in Phase 4 and no mail feature uses it yet, so transport tampering risk is low until auth/email phases arrive. |
</threat_model>
