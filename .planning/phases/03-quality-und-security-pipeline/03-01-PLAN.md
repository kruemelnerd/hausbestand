<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| pull_request payload -> GitHub Actions runner | Untrusted contributor changes control the code and manifests being scanned. |
| repository contents -> security scanners | Secrets or vulnerable manifests cross into automated tooling that must fail closed without leaking data. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | T (Tampering) | Playwright regression contract | mitigate | Keep the new E2E test pinned to existing `data-testid` selectors and disabled-state assertions so later UI drift cannot silently weaken the shell contract. |
| T-03-02 | D (Denial of Service) | Playwright pipeline runtime | accept | The added test stays inside the current single-page shell flow, so runtime increase is negligible versus the existing smoke suite. |
| T-03-03 | I (Information Disclosure) | Trivy secret scanning output | mitigate | Use fail-only scan output and avoid artifact uploads or debug dumps in `security.yml` so secret findings do not get republished. |
| T-03-04 | T (Tampering) | Dependency review gate | mitigate | Lock the workflow to read-only permissions and explicit `config-file` thresholds so PRs cannot bypass severity/scope policy via ad-hoc action inputs. |
</threat_model>
